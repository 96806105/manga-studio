Priority Opportunities

P0 - Broken Data Flow (Impact: Critical, Effort: Low)

App.tsx:13 - api.getProjects().then(p => { projectsState; }) references the atom but never sets it. Projects are never loaded into Recoil state, so the sidebar and dashboard show empty lists on initial load.

Fix: Replace with set(projectsState, await api.getProjects()) or use useRecoilValueLoadable.

P0 - API Path Mismatch (Impact: Critical, Effort: Low)

Backend routes use /api/v1/projects/ (trailing slash) but frontend calls /api/v1/projects (no trailing slash). With redirect_slashes=False, all API calls return 404 or serve the SPA index.html instead.

Fix: Either add trailing slashes to all frontend API calls, or configure redirect_slashes=True in FastAPI and ensure the catch-all route does not intercept.

P1 - Unused/Dead Models (Impact: High, Effort: Low)

models.py defines Task model that is imported zero times anywhere. Character model exists but has no API endpoints. Project.settings JSON field is never read/written via API.

Fix: Remove Task model. Either create CRUD endpoints for Character or remove it. Remove unused imports in generation.py.

P1 - Hardcoded Configuration (Impact: High, Effort: Medium)

database.py hardcodes SYNC_DB_URL = "sqlite:///./manga-studio.db" instead of using settings.DATABASE_URL. video_service.py hardcodes "./exports" instead of settings.EXPORTS_DIR.

Fix: Create a centralized path configuration and inject it through services.

P1 - Missing Type Safety (Impact: High, Effort: Medium)

store/index.ts uses atom<any[]> for scenesState and shotsState. client.ts uses request<any> everywhere. generation.py endpoint accepts data: dict with no validation.

Fix: Define typed interfaces for scenes, shots, and API request/response payloads.

P2 - Dead Code (Impact: Medium, Effort: Low)

image_service.py:8-13 - The if not settings.POLLINATIONS_API_KEY block reassigns api_key to an empty string, but api_key is never used. The variable is shadowed from the outer scope but the logic is inverted and dead.

generation.py:7 - Imports ShotUpdate from schemas but never uses it.

scenes.py:3 - Imports Project but never uses it.

export.py:7 - Imports uuid but never uses it.

P2 - Complex Nested Logic (Impact: Medium, Effort: Medium)

script_service.py:43-56 - Deeply nested conditional JSON parsing with 5 levels of isinstance checks. Should be extracted into a dedicated parser function with clear error handling.

P2 - No Debouncing on Input (Impact: Medium, Effort: Low)

ShotEditor.tsx:62 - api.updateShot(currentShot.id, { description: e.target.value }) fires on every keystroke. Should debounce or use a save button.

P3 - Deployment Issues (Impact: Low, Effort: Medium)

docker-entrypoint.sh uses python instead of /opt/venv/bin/python. Models are never auto-downloaded.

P3 - Security Hardening (Impact: Low, Effort: Medium)

CORSMiddleware allows all origins. Settings.tsx sends API keys to api.updateProject('settings', ...) but no such endpoint exists - keys would be lost.

Grill-Ready Questions

Which opportunity should we dig into first?

  1. P0: Broken Data Flow - Projects never load into state. Without this, the entire app shows empty data on refresh. Quick fix, high impact.
  2. P0: API Path Mismatch - App is non-functional until API calls match backend routes. This is the #1 blocker for using the app.
  3. P1: Unused/Dead Models - Cleaning up dead code improves maintainability and reduces confusion.
  4. P1: Hardcoded Config - Centralizing paths makes the app portable and Docker-friendly.
